# 产品更新：阶段 8E——AI 行为系统与主动监控

## 一句话

Personal Media Ops 现在把“持续关注一个目标”建模为 Monitoring Mission：AI 先理解用户真正想知道的变化，用户确认后才按受控预算运行，并将与上次已知状态相比的高价值变化送入发现收件箱。

## 用户闭环

```text
自然语言关注目标
→ AI 监控理解卡
→ Owner 确认
→ Monitoring Mission
→ 现有 Research Runtime 与单 Worker
→ 基线比较变化
→ 事件合并、来源独立性与噪音过滤
→ 发现收件箱 + 站内通知
→ 已读 / 稍后 / 忽略 / 继续研究 / 加入研究空间
→ 记忆更新与后续监控
```

## 用户可用能力

- 从“监控任务”创建 topic、entity、creator、event、research_question 或 query 监控。
- 创建分两步：填写“你希望持续了解什么变化”，查看监控目标、基线、关注/忽略范围、平台、频率、证据要求和预算，再确认创建。
- 任务详情固定为概览、重要变化、运行记录、已知基线、监控范围、预算和技术详情。
- 支持立即运行、每日、每周和受限自定义频率；任务支持暂停、恢复和归档。
- 第一次运行建立 baseline，不把历史内容伪装成“新变化”；没有实质变化时保持 `no_meaningful_change` 并静默。
- 高价值变化以 `monitoring` 来源进入现有发现收件箱，并提供站内通知、已读、稍后、忽略、继续研究和加入研究空间。
- AI 模型中心提供 Prompt Registry 的当前版本、候选版本、Eval 结果、显式激活和回滚入口；普通用户不能编辑系统 Prompt。

## AI 质量与安全边界

- 固定 Eval Dataset 覆盖产品探索、用户痛点、产品比较、趋势变化、事实验证、创作者监控、产品更新、事件追踪、负向反馈、内容机会、证据不足和平台不可用。
- 历史任务 Replay 只读取 Recorded Response，不重新抓取平台、不覆盖原任务、不改变生产历史。
- Context 按用户目标、已确认证据、未知/反向证据、实体事件记忆、查询轨迹和必要原文分层；Compactor 保留 content/evidence/source/time/关系标识。
- 事实必须绑定证据 ID，推测显式标记；转载不增加独立来源，单一来源不代表共识，报告组织器不能创造新事实。
- 每个 Mission 有模型调用、Token、采集、平台、时间和周期预算；全局继续保持单浏览器采集任务。
- AI 不会未经确认创建长期监控、扩大范围、自动发布、执行商业行动或修改 Prompt。
- 邮件、短信、微信、Telegram、MCP、知识图谱、自动发布和机会卡不属于 8E。

## 旧功能处理

旧关键词订阅和创作者观察数据保留为只读历史审计，不删除，也不未经用户确认批量伪造为 Monitoring Mission。可靠迁移时使用 `legacy_imported` 标记；当前主导航不恢复旧后台入口。

## 验证边界

本地门禁、迁移、前后端测试、构建与 1440×900、1280×720、390×844 视觉夹具是发布前硬门槛。平台扫码或验证码仍由用户通过生产前端完成；缺少平台认证时只能报告 `waiting_login` / `blocked_by_platform`，不能用合成变化代替真实验收。

## 下一步观察

重点观察真实 Mission 的变化准确率、无变化静默率、重复通知率、变化证据完整率和通知采纳率；没有持久化依据的指标继续标记为 `not_instrumented`，不以抓取数量替代用户价值。
